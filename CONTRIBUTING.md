# Contributing

Thank you for considering a contribution!

This project is intended to help people learn open-source collaboration. Contributions should be useful, clear, and respectful.

## Ways to contribute

- Fix a typo or clarify an explanation.
- Improve the beginner roadmap with accurate steps.
- Add a small, documented example.
- Add tests or improve error handling.
- Report an issue with steps to reproduce it.

## Before opening a pull request

1. Check existing issues and pull requests to avoid duplicate work.
2. Open an issue for substantial changes so the intended approach can be discussed.
3. Keep changes focused and explain why they are useful.
4. Test code examples locally where possible.
5. Update documentation when behavior changes.

## Pull request checklist

- [ ] The change has a clear purpose.
- [ ] Documentation is accurate and understandable.
- [ ] Code examples run as described.
- [ ] Tests pass, or testing limitations are explained.
- [ ] No credentials, private data, or generated junk are included.

Be kind in reviews. Ask questions, explain trade-offs, and assume good intent.
